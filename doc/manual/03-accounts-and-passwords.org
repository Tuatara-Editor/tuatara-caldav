#+title: Accounts and passwords
#+language: en

* Accounts and passwords

Telling Tuatara which server to sync with and where its password is kept.

** The password in the keyring

On each computer Tuatara syncs from, store the password in the desktop's
keyring. Never write it in the init file.

#+begin_example
secret-tool store --label="Tuatara calendars" service tuatara-caldav user you
#+end_example

It asks for the password. For EteSync give the one =etesync-dav manage get=
showed. For Radicale give the one you gave =htpasswd=.

** The password in a GnuPG file

Instead of the keyring, the password can be kept in a file encrypted with GnuPG
and given by a command, as mbsync's =PassCmd= gives one:

#+begin_example
printf '%s\n' 'THE-PASSWORD' | gpg --symmetric --output ~/.etesync-pass.gpg
chmod 600 ~/.etesync-pass.gpg
#+end_example

The first command asks for a passphrase for the file. Clear your shell's history
of that line afterwards, or type the password into a file and encrypt the file,
then delete it. Then give the account a =:password-command=:

#+begin_src lisp
'((:name "EteSync" :url "http://localhost:37358/" :user "you"
   :password-command
   "gpg --quiet --for-your-eyes-only --no-tty --decrypt ~/.etesync-pass.gpg"))
#+end_src

At each sync Tuatara runs the command, with no shell. A word beginning with =~/=
is a path in your home directory. The first line the command prints is the
password. gpg-agent asks for the file's passphrase in a window of its own and
remembers it for a while: 10 minutes as standard, each use counting again, so
syncing every minute keeps it remembered up to gpg-agent's limit, two hours as
standard. Then it asks again.

The password is never written anywhere. It goes from gpg to curl through pipes,
and Tuatara's own copies of it are wiped from memory once used. When the command
fails, Tuatara says so, and never says what the command printed.

** If the password was stored for calendar-sync

Before Tuatara 0.90.13 the package was called calendar-sync, and its password
was kept under the service =tuatara-calendar-sync=. Copy it to the new name
once, on each computer that has it, =you= being the account's =:user=. The
password is not shown:

#+begin_example
secret-tool lookup service tuatara-calendar-sync user you | secret-tool store --label="Tuatara calendars" service tuatara-caldav user you
#+end_example

Once ~C-c s l~ (=caldav-calendars=) lists the account's calendars, Tuatara has
found the password under its new name, and the old entry can go:

#+begin_example
secret-tool clear service tuatara-calendar-sync user you
#+end_example

** Loading the package with an account

Open your init file, add this with one of the two accounts (delete the other's
lines, or start them with =;;=, which Tuatara reads past), and save:

#+begin_src lisp
(load-package "caldav" :source "https://github.com/Tuatara-Editor/tuatara-caldav"
              :version "latest"
  :config
  (setf *caldav-accounts*
        ;; A. EteSync
        '((:name "EteSync" :url "http://localhost:37358/" :user "you"))
        ;; B. Radicale over Tailscale
        ;; (on home-server itself: "http://localhost:5232/")
        ;; '((:name "Home" :url "https://home-server.tail1234.ts.net/"
        ;;    :user "you"))
        ))
#+end_src

Start Tuatara again. It asks once whether to load the package.

** The accounts setting

=*caldav-accounts*= is a list of accounts. Each is a list of keywords and
values.

- =:name= is what its calendars' headings are named after.
- =:url= is the server's address: https, or http to this machine alone.
- =:user= is the name it signs in with.
- =:calendars= names those of its calendars to sync. Every calendar is synced
  when it is not given. ~C-c s l~ lists the names Tuatara finds.
- =:password-command= is a command that gives the password, run without a shell.

#+begin_src lisp
'((:name "EteSync" :url "http://localhost:37358/" :user "you"
   :calendars ("Personal" "Family")))
#+end_src

The address is the server's own. The calendars are found from it as CalDAV says
(the principal, then its calendar home). Each calendar is a heading of its own
in the calendars' file, its address in the =CALENDAR= property.
